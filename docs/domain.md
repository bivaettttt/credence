# Credence · Требования / Requirements

Учебный процесс финансирования вымышленных компаний объединяет подачу, проверку комплектности, объяснимую оценку, решение двух сотрудников и ответ на предложение. Среда использует синтетические рублёвые суммы. Выдача средств, реальные клиенты, БКИ, юридическое подписание и автоматические кредитные решения вне границ.

| ID | Участник / Stakeholder | Критерий / Acceptance |
|---|---|---|
| FR-01 | Заявитель ведёт учебную компанию и черновики | Доступ определяется членством. Версия защищает черновик от потери обновлений |
| FR-02 | Заявитель отправляет материалы | Два обязательных документа, условия продукта и входные данные проверяются. Снимок неизменяем и привязан к версии данных |
| FR-03 | Аналитик проверяет и запрашивает сведения | Назначается один аналитик. Возврат уведомляет заявителя. Повторная подача сохраняет новую версию |
| FR-04 | Аналитик рассчитывает учебную оценку | Сохраняются значения факторов, баллы, правила и версия методики. Старые оценки остаются в истории |
| FR-05 | Аналитик рекомендует, риск-офицер решает | Обоснование обязательно. Роли, актуальность версии, рекомендация и оценка проверяются на сервере |
| FR-06 | Заявитель отвечает на предложение | Условия взяты из решения. Срок и единственность ответа проверяются атомарно |
| FR-07 | Администратор обслуживает каталог | Новые версии условий не меняют ранее созданные снимки |
| FR-08 | Участники анализируют процесс | События, уведомления и операционные показатели читаются из PostgreSQL |
| FR-09 | Администратор воспроизводит эксперименты | Отдельный Compose-проект, реальные запросы и проверяемые результаты |

NFR-01. Значимые записи атомарны. NFR-02. Доступ проверяется по роли и объекту. NFR-03. Compose, pytest и Playwright воспроизводят проверки.

## Таблица переходов / Transition table

| Команда | Из → В | Роль и предусловие |
|---|---|---|
| submit | DRAFT / INFO_REQUIRED → SUBMITTED | APPLICANT, членство, документы FINANCIAL и REGISTRATION, диапазоны из закреплённой версии продукта |
| claim | SUBMITTED → REVIEW | CREDIT_ANALYST, назначить себя |
| validate | REVIEW → REVIEW | Назначенный аналитик, подтверждение комплектности сохранённого снимка и проверка документов |
| assess | REVIEW → REVIEW | Назначенный аналитик, комплектность подтверждена. Баллы рассчитаны из снимка |
| request_info | REVIEW → INFO_REQUIRED | Назначенный аналитик, обязательное обоснование. Оценка становится неактуальной |
| recommend | REVIEW → DECISION_PENDING | Назначенный аналитик, актуальная оценка. APPROVE или REJECT |
| return | DECISION_PENDING → REVIEW | RISK_OFFICER, обоснование |
| decide | DECISION_PENDING → OFFERED / REJECTED | RISK_OFFICER, отдельный субъект, актуальная рекомендация. APPROVE атомарно создаёт предложение |
| respond | OFFERED → ACCEPTED / DECLINED / EXPIRED | APPLICANT, проверка срока по часам БД под блокировкой |
| withdraw | DRAFT / SUBMITTED / REVIEW / INFO_REQUIRED → WITHDRAWN | APPLICANT, членство |

**UC-01–03.** Создать компанию и заявку, добавить учебные документы и передать аналитикам. Проверить поданный снимок.
**UC-04–05.** Запросить сведения. Старая оценка остаётся в истории. После повторной подачи подтвердить комплектность и вычислить новую оценку.
**UC-06–09.** Рекомендация аналитика, мотивированное решение риск-офицера, предложение и ответ заявителя.
**UC-10–11.** Отзыв и история. Терминальные заявки доступны для чтения.

**Глоссарий.** Revision — номер записи для конкурентных обновлений. Data version — номер неизменяемой подачи. Снимок — параметры заявки, компании, документов и продукта. Рекомендация — мнение аналитика. Решение — отдельная запись риск-офицера. Предложение — учебные условия с датой окончания.

## BR-01–BR-10

Положительная сумма и срок проверяются схемой. Продукт задаёт независимые границы суммы и срока. Отправляет представитель компании. Неполный комплект отклоняется до фиксации подачи. Запрос информации аннулирует актуальность оценки. Решение принимает отдельный риск-офицер. Истёкшее предложение не принимается. Критические команды привязаны к субъекту, объекту и ключу. Любой переход вне таблицы завершается 409.
